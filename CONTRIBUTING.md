# Contributing · Участие в разработке

**English** · [Русский ниже](#русский)

Start with a small, reproducible problem or a concrete creative workflow. Discuss changes that add permissions, new services, or new job types before implementing them. Reports and contributions may be in English or Russian.

1. Read [AGENTS.md](https://github.com/Shugar86/vids-studio/blob/main/AGENTS.md), the [architecture](docs/en/architecture.md), and the [testing guide](docs/en/testing.md).
2. Install development dependencies with `bun install --frozen-lockfile` and `bunx playwright install chromium`. Install Python 3.11+, Node.js 22.13+, and FFmpeg/ffprobe.
3. Keep runtime changes in the canonical source. The two profiles are generated by `scripts/build_profiles.py`; preserve their distinct extension keys, native host names, sockets, and skill names.
4. After source changes, run `python3 scripts/build_profiles.py --profile codex --target . --write`. Review the generated diff and run `bun run test`. Test a fresh Claude materialization with `VIDS_STUDIO_CANONICAL_SOURCE` pointing to this checkout; the cross-profile test must not be skipped in a contribution's full verification.
5. Update both language versions when behavior changes. Run the skill helper tests described in the testing guide when changing a helper. Build release packages with `python3 scripts/build_release.py --output dist` when changing distribution files.
6. Submit a focused pull request describing the problem, resulting behavior, relevant checks, and known limits. Include only your change.

Tests use synthetic documents, private temporary directories, and disposable Chromium profiles. Do not use your normal browser profile as a test fixture. Never include credentials, document IDs, job/control capabilities, personal screenshots, exported videos, or runtime databases in a contribution. Report security issues privately through the repository's **Security → Report a vulnerability** page; see [SECURITY.md](SECURITY.md).

Keep unknown outcomes visible. A lost response is not proof of failure and must not trigger an automatic repeat of a mutating action. Test recovery and arbitration when touching control, jobs, or downloads. A fixture test does not establish that the current Google Vids UI has been accepted live.

## Русский

Начните с воспроизводимой проблемы или конкретного сценария работы над видео. Изменения разрешений, новые внешние сервисы и новые типы заданий сначала обсудите в issue. Отчёты и предложения принимаются на русском и английском.

1. Прочитайте [AGENTS.md](https://github.com/Shugar86/vids-studio/blob/main/AGENTS.md), [описание архитектуры](docs/ru/architecture.md) и [руководство по проверкам](docs/ru/testing.md).
2. Установите зависимости: `bun install --frozen-lockfile`, затем `bunx playwright install chromium`. Нужны Python 3.11+, Node.js 22.13+ и FFmpeg/ffprobe.
3. Изменяйте общее ядро в исходном репозитории. Профили создаёт `scripts/build_profiles.py`; сохраняйте отдельные ключи расширений, имена native host, сокетов и навыков.
4. После изменения исходников выполните `python3 scripts/build_profiles.py --profile codex --target . --write`. Просмотрите сгенерированный diff и запустите `bun run test`. Проверьте свежую сборку Claude с `VIDS_STUDIO_CANONICAL_SOURCE`, указывающим на исходный checkout; в полной проверке межпрофильный тест не должен пропускаться.
5. При изменении поведения обновите обе языковые версии документации. Если меняется helper, запустите его проверки из руководства. Для изменений поставки соберите архивы: `python3 scripts/build_release.py --output dist`.
6. В pull request опишите проблему, итоговое поведение, проверки и существенные ограничения. Включайте только изменения своей задачи.

Проверки используют синтетические документы, временные каталоги и отдельные профили Chromium. Не используйте обычный браузерный профиль как тестовый. Не добавляйте секреты, ID документов, токены управления и заданий, личные скриншоты, экспортированное видео и runtime-базы. О проблемах безопасности сообщайте через **Security → Report a vulnerability**; подробнее в [SECURITY.md](SECURITY.md).

Не скрывайте неизвестный исход операции: потерянный ответ не доказывает неудачу и не разрешает автоматически повторить изменение. Для правок управления, заданий и загрузок проверяйте восстановление и конкуренцию. Успешный тест на fixture не подтверждает работу с актуальным интерфейсом Google Vids.
