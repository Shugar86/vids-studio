# Проверки и границы подтверждения

[English](../en/testing.md) · [Русский](testing.md) · [Главная](../../README.ru.md)

Разделяйте **проверку исходников**, **загруженный runtime** и **поведение живого продукта**. Изолированный браузерный тест подтверждает механизм; он не доказывает такое же поведение конкретного аккаунта Google, текущего интерфейса или сгенерированного видео.

## Повтор автоматических проверок

В source checkout установите зависимости из lockfile и браузер Playwright. Если FFmpeg/ffprobe отсутствуют, установите их штатным пакетным менеджером вашей среды.

```sh
bun install --frozen-lockfile
bunx playwright install chromium
python3 scripts/build_profiles.py --profile codex --target . --write
bun run test
python3 -I -m unittest discover -s skill/google-vids/tests
python3 -I -m unittest discover -s skill/vids-director/tests
```

Полный набор включает Python unit/process tests и Node tests. Браузерные фикстуры используют временные профили и локальное или перехваченное содержимое. Они не подключаются к пользовательскому Chrome и не редактируют реальный Google-документ. Медиа-проверки создают небольшие локальные материалы и используют FFmpeg/ffprobe.

В материализованном профиле укажите полный source checkout для межпрофильного теста:

```sh
VIDS_STUDIO_CANONICAL_SOURCE=/absolute/path/to/vids-studio bun run test
```

Без явного источника cross-profile source test в отдельном архиве профиля может пропускаться. Такой прогон нельзя называть полной проверкой исходников. Также запустите тесты навыка профиля: `skill/google-vids/tests` для Codex или `skill/vids-director/tests` для Claude Code.

Полезные узкие проверки:

```sh
node --test tests/jobs.test.mjs tests/export-watch.test.mjs
node --test tests/profiles.integration.test.mjs
python3 scripts/build_profiles.py --profile codex --target /absolute/installation/codex --check
python3 scripts/build_profiles.py --profile claude --target /absolute/installation/claude --check
```

`--check` сверяет управляемые файлы и возвращает ненулевой код при расхождении. Он не перезагружает процессы и не авторизует AI-клиент.

## Что проверяет набор

| Область | Свидетельство тестов |
| --- | --- |
| Сборка профилей | Разные identities, детерминированный общий build, новые targets, защищённые обновления и состав релизов |
| Setup | Сохранение посторонних настроек, отказ при коллизии, точный откат и проверка prerequisites |
| MCP-транспорт | Реальные локальные MCP-клиенты/native processes; стандартные text/image responses |
| Владение документом | Независимость документов, отказ второму владельцу одного документа, долговременный unknown и fencing поколений |
| Драйвер браузера | Проверка цели/документа, Unicode, snapshots, drag, перехват upload и screenshot recovery |
| Наблюдатель экспорта | Настоящий MV3 watcher во временном Chromium; HTTP/redirect/blob, порядок событий и отказы сопоставления |
| Export jobs | Durable intent, сохранённый доступ к job, restart/recovery, отмена, отсутствие автоматического replay и проверка MP4 |
| Медиа-помощники | Реальные небольшие медиа/изображения, кадры/alpha, история дублей и устаревание зависимых проверок |

Фикстуры проверяют известные сбои, а не все варианты чередования событий и будущие версии браузера. Для нового поведения выбирайте соответствующий regression test; тест, повторяющий детали реализации, сам по себе не добавляет уверенности.

## Живая проверка чтения

После reload расширения, явного подключения нужного документа и обновления MCP выполните в каталоге профиля:

```sh
node scripts/live_smoke.mjs --document EXACT_DOCUMENT_ID
```

При необходимости добавьте `--screenshot /absolute/new-file.png`; файл должен быть новым, путь — абсолютным. Скрипт проверяет совместимость и точный документ, получает собственное управление, делает observe, получает стандартный PNG response и освобождает управление. Фильм не меняется. Ошибка release остаётся явным провалом. В печатное evidence не попадают сырые capabilities или полное DOM-содержимое.

Запустите проверку отдельно для каждого профиля. Успешный SDK smoke подтверждает транспорт и текущее подключение. Он не доказывает, что открытый ранее чат перечитал инструменты или модель клиента правильно следует творческому навыку.

## Текущая граница подтверждения

Реализация 0.3 имеет автоматическое покрытие обоих профилей и изолированных браузерных механизмов. Публичный пакет намеренно не включает приватное содержимое проектов, состояние локальной установки и исторические снимки фильмов.

### Наблюдение реального экспорта · 22 октября 2026

Публичный [деморолик «Саша и лампа»](demo.md) экспортирован из Google Vids на Linux с профилем Codex. MP4 получен и отдельно проверен: декодированные кадры, сохранность потоков и тайминг субтитров. Публикация именно этого деморолика разрешена; приватные ссылки на редактор и сырые логи не включены.

Задание инициировало экспорт один раз, редактор сообщил об успешной выгрузке. При этом watcher остался в состоянии `armed`, без принятого GUID или ID загрузки. Задание перешло в `needs_reconciliation` с `EXPORT_WAIT_EXPIRED`, затем было отменено без повторного экспорта. Содержимое файла проверено отдельно; его имя и время изменения не считались доказательством связи с браузерным событием.

**Проверка файла пройдена; автоматическое подтверждение принадлежности загрузки не прошло приёмку.** Версия загруженного runtime отсутствует в сохранённых свидетельствах. Поэтому наблюдение нельзя приписать сборке v0.3.0 или распространить на Claude Code, Windows и macOS. Проверка кадров и техническое сравнение звука также не подтверждают свежий просмотр в реальном времени и прослушивание; см. [границы проверки ролика](demo.md#границы-проверки).

Явная живая проверка с **текущим загруженным build** ещё требуется для:

- typed-рецепта `export_mp4` на фактическом Google Vids, включая referrer документа и download events;
- зависимых от аккаунта генераций, аватаров, голосов, субтитров и других функций выбранного проекта;
- слышимого, видимого и режиссёрского качества каждого нового видео или дубля;
- восстановления конкретного живого зависания браузера: fixture с задержанным read не подтверждает все реальные сбои.

Export fixture намеренно передаёт полный referrer документа через `referrer=unsafe-url`. Она подтверждает watcher при этих условиях. Реальный Vids может не передать referrer либо ограничить его origin; реализация отклоняет такую атрибуцию, не выбирая соседний файл. Устаревающие CDP download events и параллельные загрузки одного документа имеют дополнительные ограничения в [jobs](jobs.md).

Прежняя успешная загрузка или наблюдаемое меню не доказывают новый экспорт, активацию новой сборки или функцию другого аккаунта. Записывайте результат с version/profile и типом среды, исключая из публичного evidence конфиденциальный материал проекта.

## Сборка релизов

```sh
python3 scripts/build_release.py --output dist
```

Команда создаёт ZIP исходников, Codex и Claude, `SHA256SUMS` и `release-manifest.json`. Зависимости, runtime stores, backups конфигурации и локальная работа исключаются. Перед публикацией проверьте архивы, hashes и установки обоих профилей. Сама сборка не создаёт GitHub release и не отправляет исходники в remote.

## Native Windows/macOS CI

Запустите `python tests/platform_smoke.py`, установив Windows-зависимость при необходимости. Полный regression suite выше выполняется на Linux; нативный CI Windows/macOS проверяет оба профиля, установку и откат, владение, транспорт, медиа и воспроизводимость архивов. Используется имитация Chrome, без утверждения о живой приёмке Google Vids. [Руководство по платформам](platforms.md).
