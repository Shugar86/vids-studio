# Решение проблем

[English](../en/troubleshooting.md) · [Русский](troubleshooting.md) · [Главная](../../README.ru.md)

Начните с `vids_diagnostics` и `vids_status`. Они не подключают вкладки, не получают управление и не меняют документ. Перед изменениями установите, какой профиль, build и документ реально активны.

| Симптом | Проверка и следующий шаг |
| --- | --- |
| Нет MCP-инструментов | Запустите setup без `--install` в каталоге нужного профиля. Проверьте запись MCP клиента и обновите/перезапустите его MCP-подключение. Claude Code и Claude Desktop настраиваются по-разному. |
| `connected: false` | Возможно, native host не запущен. Проверьте нужное расширение и явно подключите вкладку Vids. Сверьте manifest host и исполняемый Python-файл; не ищите другие вкладки автоматизацией. |
| `attached: false` | Откройте нужный Vids и подключите его кнопкой соответствующего расширения. Один status подключение не создаёт. |
| `RECONNECT_REQUIRED` | Завершите активную работу, перезагрузите карточку расширения, подключите нужную вкладку и обновите MCP. Сравните profile/version/build MCP/host/extension. Пересборки файлов недостаточно. |
| `CONTROL_BUSY` | Документом владеет другая задача. Дождитесь освобождения её lease. Не используйте чужой токен, удаление состояния или другой профиль для обхода владения. |
| `STALE_SNAPSHOT` или старая сессия | Получите текущий status, собственное действующее управление и свежее наблюдение. Не используйте координаты и токены прежнего подключения. |
| `BROWSER_RECOVERING` | Предыдущее screenshot-чтение ещё завершается. Проверяйте status до `recovery: null`, затем выполните новый observe. Ввод во время recovery не отправляйте. |
| `BROWSER_TIMEOUT` после мутации | Исход может быть неизвестным. Осмотрите квитанцию и документ; не повторяйте click/type/upload только из-за тайм-аута ответа. |
| `mode: reconcile` | Осмотрите документ и передайте содержательное evidence в `vids_reconcile_control`. Старый unknown сохраняется; это не разрешение повторить действие. |
| Export job требует reconciliation | См. [jobs](jobs.md): неизвестные подписи UI, referrer, сессия и неоднозначная загрузка останавливают сценарий. Не ищите «самый свежий MP4» наугад. |
| Setup сообщает о коллизии | Обнаружена другая регистрация, профиль, навык или путь. Осмотрите названный конфликт, сохраняя существующие настройки. Setup намеренно не выбирает, какую установку заменить. |
| Host не исполняется после распаковки ZIP | Некоторые архиваторы теряют Unix modes. В выбранной установке выполните `chmod +x native/bridge.py`, затем повторите setup без `--install`. |

## Обновите нужный компонент

**Reload** расширения, **reconnect** вкладки и **refresh** MCP решают разные задачи:

1. Дождитесь завершения активной работы и освободите управление задачи.
2. В `chrome://extensions` нажмите **↻ на карточке нужного расширения**. Общая кнопка «Обновить» — другая операция.
3. Вернитесь в нужный документ Vids и явно подключите его этим расширением.
4. Обновите MCP-подключение соответствующего клиента.
5. Проверьте совместимость и документ. Получите новые управление и snapshot.

Для общей координации обновите **оба** профиля. Работающий старый host 0.1 не соблюдает coordinator 0.2. Не прерывайте активную генерацию другой задачи только ради перечитывания файла.

## У восстановления screenshot есть предел

Только для screenshot-чтений драйвер может вернуть `BROWSER_TIMEOUT` через десять секунд, сохранив барьер для исходного read. Ему даётся ещё до десяти секунд на завершение. Позднее изображение отбрасывается; действия блокируются, старые снимки недействительны. Если чтение не завершается, attachment отзывается.

Это восстановление задержанного read, а не постоянно зависшего renderer Chrome. Оно не выводит Chrome вперёд, не подключается заново и не повторяет ввод автоматически. Тайм-аут мутации обрабатывается консервативно.

## Загрузка и ввод

- Используйте `vids_upload_via_picker`, если input возникает после кнопки Upload. Не обслуживайте системное окно вводом рабочего стола.
- Координаты задаются в CSS-пикселях viewport; учитывайте масштаб снимка.
- Проверяйте цель и результат правки. Приём события не доказывает изменение сцены приложением.
- Unicode-ввод не зависит от раскладки. Русский язык в конкретной AI-функции голоса/генерации проверяется отдельно.
- Закройте DevTools управляемой вкладки, если они заняли debugger. После завершения активной работы подключитесь явно.

## Что приложить к сообщению об ошибке

Полезный отчёт содержит commit/version, профиль, версии ОС/браузера/Node, минимальную последовательность, ожидаемый и фактический результат, код ошибки и очищенную от приватных данных диагностику совместимости. Укажите, использовалась изолированная фикстура или живой Vids и был ли текущий build действительно загружен.

Не прикладывайте сырые настройки клиента, rollback-файлы, cookie, capabilities, базы jobs, приватные медиа и полные снимки редактора. `bridge.log` ограничен и содержит только метаданные, но перед публикацией всё равно проверьте отчёт. Для уязвимостей используйте [security policy](../../SECURITY.md) репозитория.
