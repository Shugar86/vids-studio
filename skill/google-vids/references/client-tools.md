# Общие инструменты Codex и Claude

Оба профиля получают одинаковые помощники и шаблоны. Режиссура, принятие дублей и пределы проверки — в общем [workflow](workflow.md). Перед запуском проверь аргументы текущего скрипта; локальные инструменты не дают доступ к вкладке Vids и не разрешают новые сервисы или установку пакетов.

## Слои и раскадровка

Копируй `assets/layers.html` в рабочий `layers/<сцена>.html`. Общие цвета, шрифты, формат и композицию задавай под ролик; значения шаблона не становятся требованиями 9:16 или безопасных зон площадки. Каждый `.layer` с `id` описывает конечное положение элемента на полном кадре; движение задаётся в Vids.

```bash
node scripts/render_layer.mjs layers/b4.html layers/png/b4-note-v1.png --show headline
```

Результат — прозрачный PNG полного кадра. `--guides --opaque` создаёт проверочный снимок; его не импортируют как финальный слой. Код возврата 3 означает, что текст не влез: исправь раскладку. Скрипт использует изолированный offline headless Chromium для статического HTML; JavaScript документа и service workers отключены. Размер кадра и выбранного элемента ограничен, чтобы ошибочные параметры не породили огромный снимок. После импорта проверь фактический размер/позицию в Vids, а не принимай размер PNG за геометрию объекта. Текст внутри PNG не редактируется отдельно; нужные для будущих правок слова оставляй native текстом Vids.

`scripts/vendor_fonts.py` готовит локальные шрифты и `fonts/fonts.css`; передай применимую локальную лицензию через `--license-file` и её источник через `--license-source`. Helper сохраняет лицензию и provenance/hashes, но не устанавливает разрешённость конкретного использования; перед сетевой загрузкой шрифта проверь, что это входит в разрешённую подготовку. Кириллицу проверяй в полученном кадре и native тексте, не по латинскому образцу.

Если в клиенте доступен тип артефакта Design, можно показать ключевые кадры и заметки (речь, действие, способ сборки в Vids) на одном канвасе. Артборды и слои используют одну раскладку и токены. Следуй реальной схеме артефакта; при недоступности канваса достаточно таблицы и отрендеренных кадров. Для короткого программного клипа см. общий [motion-inserts.md](motion-inserts.md) и локальную справку [hyperframes.md](hyperframes.md); готовый клип остаётся одним импортированным медиа, а не набором native объектов.

## Реальные сайты

```bash
node scripts/capture_site.mjs URL --out work/assets/site-v1 --scroll 6 --locale ru-RU
```

Размеры, масштаб, высота захвата и длительность прокрутки ограничены; допустимые значения показаны в диагностике аргументов. Кодирование отменяется при потере медиа-допуска с подтверждением завершения процесса. Это снимок/прокрутка разрешённого сайта через собственный headless Chromium без пользовательского профиля, системного ввода и clipboard. Снимок обрезается по последнему содержимому страницы. Не переноси cookies для доступа; результат проверяй на реальные данные, ошибки загрузки и кадрирование. Опция `--scroll` анимирует высокий PNG страницы и не доказывает её интерактивное поведение. Сборка записи остаётся в Vids.

## QA экспорта

```bash
python3 scripts/qa_export.py exports/vN.mp4 --out qa/vN --profile social
python3 scripts/asr_blind.py exports/vN.mp4 --out qa/vN-asr --language ru
```

`qa_export.py` создаёт `findings.md`, `report.json` и `sheets/`: сетку всего видео 2 кадра/с, первые/последние 3 секунды и кандидаты стыков ±0.5 секунды при 10 кадрах/с, листы с направляющими безопасных зон. Исходник не меняется; непустой каталог вывода отклоняется. ffmpeg ограничен двумя потоками.

Профили `social`, `web`, `broadcast` задают диагностические пороги, а не цель каждого ролика. Скрипт отмечает поздний звук, тишину, неподвижность, длину плана, громкость и пики; эти находки требуют проверки по заказу и материалу. Отсутствие звука или subtitle track в немом заказе не дефект. Скрипт не слышит интонацию, не читает смысл и не подтверждает вшитые титры или плавность. Общие инструменты `review_sheet.py` и `inspect_media.py` позволяют явно задать границы/пороги.

`asr_blind.py` использует существующие whisper.cpp и модель из `~/.cache/hyperframes/whisper`, ничего не скачивая. Сначала сохрани транскрипт без сценария; лишь после фиксации сравни со сценарием, в том числе через `--compare`. Для короткой пробы есть `--offset`, `--duration`, `--model base`. Второй Whisper может повторить ошибку первого; совпадение текста не закрывает сомнительное произношение.

## SRT

```bash
python3 scripts/script_srt.py qa/vN-asr.words.json script.txt --out captions.srt
```

Помощник берёт текст сценария и время из ASR. Поэтому его выход — кандидат, а не доказательство произнесённых слов: до импорта сверь расхождения со звуком и поправь реальную речь или текст captions. Не заменяй спорные слова ожидаемым сценарием ради PASS. Мост поддерживает `.srt`/`.vtt` в проверенном пути upload; видимость, синхронизацию и soft/burned captions проверяй отдельно в экспорте.

## Монтаж в назначенном ролике

`vids_ui.py` объединяет операции `scenes`, `replace`, `delete`, `add`, `fullframe`, `transition`, `playhead0` и `release`. Каждый шаг использует MCP своего профиля, свежий snapshot и новый operation ID. `add` проверяет пустую новую последнюю сцену; `fullframe` сверяет Width/Height/X/Y; `transition` — выбранный переход и его длительность. Эти проверки не заменяют просмотр результата и экспорт.

Помощник монтажа поддерживает Linux/macOS; на Windows используйте те же штатные MCP tools напрямую. Нужны уже установленные Node, Python и Pillow. Команды примера запускаются из каталога skill; реальные пути, document ID и session UUID берутся только из назначения текущей задачи:

```sh
mkdir -p -m 700 work/private-vids
python3 scripts/vids_ui.py acquire work/private-vids/control.json \
  --session SESSION_UUID --document DOCUMENT_ID --ticket-file - --label "My video task"
export VIDS_CONTROL=work/private-vids/control.json
python3 scripts/vids_ui.py scenes
python3 scripts/vids_ui.py replace 4 EXPECTED_MEDIA_NAME work/clip.mp4
python3 scripts/vids_ui.py fullframe 1920 1080
python3 scripts/vids_ui.py transition 4 Dissolve 0.6
python3 scripts/vids_ui.py release
```

Popup-код передавайте через stdin или приватный файл 0600; не в argv/логе. Соседний `control.json.binding.json` сохраняет собственную authority до claim. Не удаляйте его при потерянной квитанции. Helper не выбирает свободную вкладку, не заимствует токен, не повторяет неизвестный acquire и не делает автоматический resume. Release освобождает writer lease, но сохраняет binding. После reconnect нужны собственные credentials, новый ticket и предусмотренное протоколом fencing.

Существующий control file обязан содержать `schemaVersion: 1`, `bindingId`, `documentId`, `profileId` (`codex`/`claude` строго своего профиля), `sessionId` и собственный `controlToken`; файл 0600, каталог 0700. При ошибке снимка старый файл не используется. При timeout мутации цепочка останавливается: свежие status/observe и reconciliation предшествуют следующей правке. Не повторяйте намерение другим жестом. Монтажные эвристики рассчитаны на проверенные английские labels и геометрию; при неподдерживаемом layout используйте свежие штатные observations, не подбирайте координаты вслепую.

Прежняя команда filename-based `export` отключена. Пользуйтесь типизированными `vids_job_start/status/result` и проверкой provenance загрузки; совпадение имени файла не является такой проверкой.

## Проверка склеек

```sh
python3 scripts/cut_check.py exports/v1.mp4 --out qa/v1-cuts --plan 86,258,299 --around 2.37,8.6
```

Локальный помощник сопоставляет покадровые cuts с планом, отмечает короткие white/black flash и собирает полосы титров около стыков и заданных моментов. Источник не меняет; требует новый каталог вывода, Pillow и FFmpeg/ffprobe. Находки — эвристика для просмотра, не доказательство качества монтажа или восприятия речи.

## Низкоуровневый клиент

`scripts/vids_call.mjs` — вспомогательный клиент MCP своего профиля. Путь определяется относительно skill или через `VIDS_CODEX_BRIDGE` / `VIDS_CLAUDE_BRIDGE`; идентичность проверяется до запуска. Чужой профиль не используется как fallback. Для JSON аргументов используйте `-` и stdin, чтобы не помещать capability в argv. Предпочитайте доступные штатные инструменты. Helper не отменяет discovery, владение документом, свежесть snapshot или остановку после unknown.

Тяжёлые команды `qa_export`, `cut_check`, `asr_blind`, `render_layer` и `capture_site` ждут общий медиа-допуск между профилями. Это ограничение локальных процессов, не число роликов. Не запускайте вложенный helper, уже удерживая его permit, и не удаляйте marker после аварийного завершения без предусмотренной проверки.

## Поиск скачанного файла

`python3 scripts/find_downloads.py --name "Мой ролик" --since "2026-10-23T10:00:00Z"` показывает кандидатов MP4 в настроенной XDG-папке загрузок, Downloads и Загрузки. Для другой папки передай `--directory /полный/путь`. Поиск ограничен и не рекурсивен; самый новый файл не выбирается автоматически. Сверь содержимое, длительность и версию сцен со своим проектом. Кандидат не является доказательством связи с экспортом. Отсутствие результата не разрешает новый экспорт.
