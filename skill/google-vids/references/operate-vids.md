# Работа с интерфейсом

Для повторяемых операций монтажа есть общий [помощник монтажа](client-tools.md#монтаж-в-назначенном-ролике); он использует те же MCP guards и собственную привязку задачи.


Для каждого подключённого ролика текущего профиля сначала выполните [привязку этой задачи](parallel-sessions.md). `vids_status` без sessionId возвращает список, а не выбирает вкладку; диагностика и все действия адресуются точной сессии.

## Подключение и область действия

Используй выбранную пользователем вкладку и проект. Сверь адрес `docs.google.com/videos/d/<id>`, название, режим редактирования и текущую сцену. При нескольких профилях браузера не подменяй сессию догадкой. Авторизация на работу с одним роликом не означает доступ к другим файлам или разрешение поделиться ссылкой публично.

Вызови `vids_diagnostics` и `vids_status`, прочитай текущие схемы инструментов. Для runtime 0.2 требуется `compatibility.ready: true`: profile/version/buildId у MCP, host и extension должны совпасть. Если diagnostics отсутствует, новая версия не подтверждена. `vids_observe` даёт состояние для действий, `vids_screenshot` — визуальную проверку. Наличие инструмента в списке не подтверждает соединение с браузером.

В текущем MCP `vids_status` возвращает плоские поля состояния, например `{connected, attached, sessionId, ...}`. У `vids_observe` данные вложены в `{result: {snapshotId, nodes, ...}}`; у мутаций также есть `result` и может быть `receipt`. Читай фактический ответ, не ищи `snapshotId` на неверном уровне. `vids_screenshot` возвращает метаданные отдельно от MCP ImageContent: для координат действия в CSS-пикселях раздели координаты пикселей изображения на `image.scaleX` и `image.scaleY` соответственно. Не подставляй DPR вместо этих масштабов. Screenshot создаёт новый snapshot без AX-ссылок на узлы; для действия по узлу после screenshot снова вызови `vids_observe` и возьми новые ссылки и `snapshotId`.

Если Vids MCP недоступен, не переходи к системной мыши, клавиатуре или desktop automation. Подготовь сценарий, карту сцен и локальные материалы, честно отделив их от не выполненного монтажа, и назови необходимое восстановление подключения. Не устанавливай автоматически расширение, другой профиль Chrome или новый сервис.

## Фоновая работа и параллельные агенты

Пользователь должен иметь возможность работать в других приложениях, пока идёт монтаж. Все действия выполняются через MCP прямо в подключённой вкладке: не активируй окно/вкладку, не используй системный ввод или буфер обмена. `vids_press_key` — событие внутри целевого документа, а не системная клавиша; сочетания для clipboard, управления браузером и ОС запрещены. Не обходи этот запрет через меню Copy/Cut/Paste, shell, другой инструмент или системный диалог. Для текста используй Unicode-ввод, для файлов — один из поддерживаемых путей загрузки ниже. Если операция выходит за них, требует микрофона/записи экрана либо перехватывает desktop, останови только её и явно обозначь требование.

После `vids_status` получи управление через `vids_acquire_control` со своими подтверждёнными `bindingId`/`bindingToken`, точными `sessionId` и `expectedDocumentId`, коротким `ownerLabel` текущей задачи. Сохрани выданный `controlToken` и передавай его в наблюдения, снимки и действия. При занятом управлении продолжай независимую работу; не размыкай чужое соединение и не пытайся подбирать токен. Когда монтаж завершён или передаётся другому исполнителю, освободи управление через `vids_release_control`. В текущей версии управление истекает через 15 минут бездействия; действия владельца продлевают его, а при долгом ожидании есть `vids_renew_control`. Выполняющийся запрос, в том числе с неизвестным исходом после timeout, не позволяет передать управление до его завершения или переподключения. При утрате управления заново получи его и свежий снимок. Актуальные сроки сверяй с ответом сервера.

Ошибка `RECONNECT_REQUIRED` означает несовместимые загруженные слои; diagnostics указывает runtime MCP/host/extension. После изменения host достаточно явного переподключения, после изменения extension нужен reload карточки, после изменения MCP — обновление инструментов клиента. Это делает пользователь; не переходи к desktop automation. Несовместимое соединение отвергается до действий в браузере; прежний снимок после переподключения недействителен.

После изменения файлов расширения требуется именно **↻ на карточке Vids Studio в `chrome://extensions`**, затем подключение нужной вкладки через popup. Общая кнопка «Обновить» вверху страницы и простое переподключение не заменяют reload кода. Планируй его в удобной паузе перед использованием обновлённой функции, после завершения выполняющихся запросов; не прерывай монтаж ради ритуального обновления. Дождись завершения старого host, проверь status и заново получи управление/снимок. Наличие метода в capabilities не доказывает, что загружена последняя правка его реализации.

Одним document ID управляет один агент во всех обновлённых профилях, даже если открыты разные вкладки того же документа. Разные документы независимы. Старый host 0.1 в общем арбитраже не участвует: оба профиля должны быть перезагружены. Делегируй другим сценарий, подготовку медиа и независимую проверку; токен не передавай. Блокировка не запрещает ручное редактирование человеком: если он меняет тот же ролик, нужна передача управления.

После сбоя прежнего владельца новый runtime не забирает документ по времени или PID. Сначала должно быть подтверждено отключение старого debugger поколения. При `mode: reconcile` наблюдай документ без мутаций; затем `vids_reconcile_control` с evidence осмотра или явного восстановления сохраняет старый `unknown` и разрешает новые намерения. Старое действие автоматически не повторяется. Недоступность registry не разрешает ввод, но diagnostics и локальная подготовка остаются доступны. Неизвестный исход сохраняется в журнале и не превращается в разрешение повторить действие.

Работа в фоновой вкладке не гарантирует работу после сна устройства, выгрузки вкладки или закрытия Chrome. Не скрывай остановку браузера и не переключайся на системный ввод для её обхода.

## Цикл наблюдения и действия

1. Получи свежий `vids_observe` с действующим `controlToken`; проверь выбранную сцену, объект, открытый диалог и `sessionId`/`snapshotId`.
2. Выбери одну осмысленную операцию. Цель, текст, координаты или клавиши должны соответствовать текущему состоянию и фактической схеме инструмента.
3. Для `vids_click`, `vids_drag`, `vids_scroll`, `vids_type_text`, `vids_press_key`, `vids_upload`, `vids_upload_via_picker` передай требуемые идентификаторы, `controlToken` и новый `operation_id` этой операции. Не переиспользуй идентификатор для иной команды.
4. Проверь квитанцию, дождись готовности UI и наблюдай результат. После мутации, смены окна, прокрутки или внешнего редактирования не используй прежние цели/координаты без нового наблюдения. Короткая пауза помогает интерфейсу обновиться: в живом опыте помогли 450 мс, но это не гарантия и не обязательная задержка. Следующий шаг определяет фактическое состояние.

Предпочитай короткие цепочки через видимые кнопки и canvas со свежим observe после каждого шага. Длинная последовательность раскрытых меню без промежуточных проверок легко теряет выделение и фокус; разбивай её на наблюдаемые состояния.

Параметры клика и ввода определяются схемой сервера; этот документ не вводит несуществующие поля. Семантические имена вроде `add_scene`, `set_duration`, `set_voice` — намерения монтажа, а не доступные RPC.

`observe` может показать число сцен, переходы, текущую позицию и общую длину. Это не полный timeline: в проверенном AX не было длительностей всех сцен и их точных границ. Не восстанавливай их из ширины thumbnails или описания музыкальной дорожки. Для плотной проверки стыков записывай подтверждённые границы при монтаже; кандидаты смены кадра из экспорта служат подсказками, не моделью сцен Vids.

**Неопределённый исход:** после тайм-аута проверь `vids_status`; при действующем подключении перечитай состояние через observe/screenshot, а при отключении сначала восстанови сессию и управление. Не повторяй мутацию с прежним или новым `operation_id`, чтобы проверить, выполнилась ли она. Native host хранит квитанции только в памяти текущего процесса: до 900 секунд (15 минут), максимум 512 записей. Кэш может быть утрачен после истечения срока, вытеснения, перезапуска или переподключения; тот же ID тогда не гарантирует идемпотентность. Квитанция `outcome: unknown` остаётся неизвестной даже после позднего ответа расширения, а идентичный повтор в пределах кэша вернёт тот же `unknown`. Установи по текущему проекту наличие созданного объекта или статус операции; только определённый результат позволяет принять новое решение о дальнейшем действии. Если исход по-прежнему неоднозначен, не выполняй зависимую мутацию вслепую.

При разборе обрыва сохраняй ответ исходной операции и время, а затем статус: `NOT_CONNECTED` у следующего снимка означает, что соединение уже отсутствовало, и не устанавливает причину. Для screenshot обновлённый драйвер изолирует зависшее чтение, как описано ниже; не переноси это поведение на мутации или неизвестную загруженную версию. Native transport может отдельно вернуть `DISCONNECTED`. Автоматические тесты runtime проверяют защитное поведение, но не устанавливают причину конкретного обрыва. Не заменяй эту диагностику увеличением тайм-аута или повторной мутацией вслепую.

**Устаревший снимок:** это повод обновить наблюдение, а не обойти проверку. Если два действия подряд не дают ожидаемого состояния, прекрати тот же слепой приём: проверь фокус, перекрывающий диалог, слой, масштаб и текущий объект; затем выбери иной видимый путь.

## Особенности редактора

| Намерение | Что искать в текущем UI | Проверка результата |
| --- | --- | --- |
| Изменить сцену | Выделение на основной ленте сцен | Нужная миниатюра и содержимое canvas; выделение объекта не равно выделению сцены |
| Вставить текст | Поле сценария или режим редактирования текстового объекта | Текст попал в нужный объект, не в поиск/название; сохранены кириллица и переносы |
| Сдвинуть появление объекта | Show timing / отображение времени и его дорожка | Меняется вход/выход нужного объекта, не порядок сцен |
| Подрезать клип | Playback options или подтверждённые ручки его дорожки | Выбран нужный фрагмент исходника; звук не оборван. Увеличение Playback End может растянуть сцену; изменение Start не сокращало её. Отдельно проверь длительность сцены и отсутствие пустого хвоста |
| Изменить длительность | Управление нужной сценой или ручка нужной дорожки | Сцена и объект имеют нужные времена; соседние дорожки не сдвинуты случайно |
| Добавить звук | Upload/Uploads либо текущая панель генерации | Новая дорожка появилась в нужном месте; звук реально слышен |
| Изменить громкость | Выделенная аудиодорожка → Sound | Изменён нужный источник; прослушана смесь |
| Переход/анимация | Между сценами либо панель Animation выбранного объекта | Просмотрено перекрытие/вход/выход, а не только выбран эффект |
| Воспроизвести | Видимая кнопка Play | Ролик движется, звук доступен; пробел не введён в текст |
| Экспортировать | Текущее меню File с вариантом скачивания MP4 | Получен завершённый файл именно последней версии |

Названия — ориентиры из документации Google, а не проверенные селекторы. UI может быть локализован и меняться. На canvas часть объектов может отсутствовать в дереве доступности: используй скриншот и проверяемое выделение, а не придуманный DOM. Перед перетаскиванием установи границы области, масштаб и ручку. Предпочитай видимое числовое поле, если оно действительно доступно и даёт точное изменение.

`vids_type_text` позволяет передать текст, но не доказывает поддержку русского TTS.

### Раздельные графические слои

В живом Vids проверена загрузка PNG через **Insert → Upload** с перехватом picker. Новый объект может вставиться с полями и уменьшением: исходные 1080×1920 получались 1016×1806,2 и X=Y=32. Не принимай размер файла за геометрию сцены. Выдели новый объект, открой **Format options → Size & rotation / Position**, проверь единицы и точку отсчёта. Для полноэкранного слоя задай размер сцены и X=Y=0; для прозрачного элемента — размер и координаты его полного PNG, включая прозрачные поля. При включённом **Lock aspect ratio** достаточно ширины. После каждого числового ввода и Enter перечитай значения и посмотри композицию.

В проверенном UI **Set image as background** заполнял сцену изображением. Для прозрачного переднего слоя используй геометрию объекта в **Format options**, чтобы сохранить нужные размер, позицию и независимое наложение; назначение фоном не заменяет эту настройку.

Для исправления содержимого готовой карточки проверен **Replace image**: в сцене с AI-черновиком замена PNG сохранила геометрию и вход **Rise**, что подтвердил экспорт. Это полезнее повторной вставки с нуля, но после каждой замены проверь размер, положение, Show timing и анимацию — один успешный случай не гарантирует сохранение всех свойств.

Для движения фотографии проверен путь: оставить её отдельным объектом, применить фотоэффект и поместить под текст через **Send to back**. Простое назначение того же фото фоном в этом монтаже движения не дало. Проверяй весь ход приближения, включая безопасное расстояние лица от титров, и последние кадры экспорта. В проверенном CTA **Zoom In** работал, но последний кадр сбрасывал масштаб при loop 5 и 10 с; сокращение сцены лишь переносило скачок к новому концу. **Photo effect → Breathe** с длительностью около длины сцены тоже не дал ожидаемого возврата. Название эффекта и таймер UI не гарантируют его поведение в экспорте. При таком повторяющемся дефекте отключи проблемный эффект или выбери другой проверяемый приём; не продолжай укорачивать сцену без новой гипотезы. Сохрани читаемый финал и проверь последние кадры после замены.

**Show timing** раскрывает отдельные дорожки объектов. Перетаскивание левой ручки меняет начало объекта; новая загрузка сама по себе не получает нужный вход. Для анимации только появления проверен путь **Animation → Object → Enter & Exit → Separate enter and exit animations → Enter**: выбери эффект и длительность, отдельно проверь Exit. Совместная настройка входа и выхода может убрать карточку перед склейкой, хотя по смыслу она должна остаться.

Длительность сцены и время объекта — разные изменения. Официальный путь для сцены — её синие ручки; числовое поле длительности сцены пока не подтверждено. Увеличь масштаб timeline для точности, проверь отображаемую длительность и затем экспорт. Оценка по координатам перетаскивания — целевое приближение, а не подтверждённый таймкод. [Справка точного монтажа](https://support.google.com/a/users/answer/15599399?hl=en).

В живом монтаже длительность сцены удалось изменить перетаскиванием **верхней части её правой границы**. Плашка перехода посередине границы и кнопка **+** у последней сцены перехватывали попадание. Перед drag возьми свежий screenshot и найди свободный участок ручки; после него проверь выбранную сцену, её край и изменение общего времени. Успех этого приёма не устанавливает, какая версия реализации drag была загружена в расширении.

**Точная длина через Replace video.** В одной постановочной пробе после Replace video длина сцены становилась max(длина нового клипа, конец самого длинного другого слоя), и экспорт подтверждал её кадр в кадр (14 замен, детектор склеек). Drag правой границы на 200% ошибался на несколько кадров, а сдвиг на один кадр не применялся. Для кадровой точности готовь клип нужной длины и заменяй видео. Если слой-картинка длиннее нового клипа, сцена не укоротится, и в хвосте пойдут белые кадры со слоями: дай клипу эту длину (например, статичным последним кадром) или сначала укороти слой. В наблюдавшемся UI этой пробы прямое скачивание результата AI Video из панели было недоступно; проверь текущие контролы своего аккаунта. Если прямого пути нет, проверенный способ получить точный отрезок дубля: Insert во временную сцену в конце → экспорт → кадровая вырезка нужного диапазона → Upload и Replace video в рабочей сцене → удали временные сцены. Однажды Insert положил вертикальный дубль во временную сцену обрезанной рамкой 16:9, поэтому до вырезки проверь, что дубль занимает весь кадр.

**Выбор сцены.** Узлы `Scene N of M` в AX не совпадали с положением миниатюр после удалений и при прокрученном timeline: клик по ним выделял соседнюю сцену, и так удалилась не та сцена (вернул Undo). Выбирай сцену по миниатюре со свежего снимка и подтверждай выбор по имени клипа на дорожке выделенной сцены. Высота панели timeline меняется с числом слоёв выделенной сцены, поэтому координаты пересчитывай после каждого выбора.

Проверка экспорта обязательна и после положительной квитанции: в другом drag ответ `performed: true` не устранил два белых кадра в конце первой сцены. Сверяй точный стык до/после изменения; не записывай устранение пустого хвоста по ответу инструмента или приблизительному положению ручки.

Если ручка длительности не даёт результата, проверен native обход: поставить playhead на нужный конец → **Split scene** → выделить только короткий ненужный хвост → Delete. Непосредственно перед Delete свежим screenshot подтверди выделение **одной нужной сцены-хвоста**. После клика AX может обновиться раньше раскладки; фиксированная пауза не заменяет снимок. После удаления проверь длительность, соседние сцены и сохранность нужного содержимого.

**Split scene может разделить также проходящую через сцену озвучку.** После split отдельно проверь речь, styled и soft captions: на новых границах возможны повторения слов. Не считай разделённые объекты независимыми копиями transcript; перед заменой слова проверь все его появления. Исправленный отдельный subtitle track экспортированного MP4 не исправляет captions самого проекта Vids; явно отличай такую производную версию и подтверждай сохранность видео/аудио.

В интерфейсе подтверждены вставка, геометрия и настройки анимации; их появление в UI ещё не подтверждает движение и стыки итогового видео.

После обрезки клипа сверяй **captions с оставшимся звуком**, особенно первые и последние слова. В живом экспорте `mov_text` сохранял слова исходника, уже не слышимые после trim. Проверенный путь исправления: выделить видеоклип → Captions → More → Edit transcript → нужное слово → Edit → заменить пустой строкой. Сверь актуальные пункты UI, затем проверь новый экспорт; правильная обрезка картинки и аудио не доказывает правильные субтитры.

Для отдельной озвучки путь правки transcript может выглядеть так: **voice track → Edit with transcript → нужное слово → contextual Edit → Replace selected text with new text → Replace**. Несколько соседних слов выделяй только в подтверждённо сфокусированном Transcript listbox. После Replace ссылки на options могут устареть: дождись свежего observe. Не повторяй мутацию с неизвестным исходом.

В native **Styled captions** проверь область **All scenes**, размещение и анимацию каждой сцены. Положение по умолчанию может перекрыть лицо или важную подпись. Короткие слова при Rise могут оставаться полупрозрачными, а эффект — перезапускаться на склейках. Если это мешает чтению, попробуй **Customize styling → Enter: Appear / Exit: Disappear**, затем проверь фактический экспорт; это кандидат, не универсальный пресет.

После Styled captions с областью All scenes проверь немые клипы на ошибочные caption-объекты вроде **Couldn’t generate captions**. Удаляй только подтверждённый объект ошибки после проверки его привязки; сохрани связанное видео, озвучку и нужные captions. После Replace video и общей смены стиля снова осмотри список объектов и экспорт. Чистый обзор кадров не доказывает отсутствие скрытого ошибочного объекта в редакторе.

Переход между двумя крупными надписями проверь в середине перекрытия: растворение может смешать оба текста в нечитаемый. Разведи их показ либо сократи/замени переход, затем перепроверь этот стык и общий тайминг. Выбранный Fade и число секунд сами по себе не доказывают читаемость.

После добавления или изменения перехода заново установи границы по экспорту и таймкодам captions: в живом монтаже Fade сократил общую длину и сдвинул последующие сцены. Не рассчитывай длительность как сумму прежних сцен с переходом сверху; величина сдвига относится к конкретному переходу.

### Локальные файлы и Upload

Если свежее observe показывает `file-input`, сначала установи его назначение по открытой панели и контексту: input может относиться к **AI Video → Ingredients**, даже когда нужна вставка в сцену. Только для подтверждённого назначения используй **`vids_upload`** с его `nodeRef`; этот путь не требует нажатия кнопки выбора файла. В живом Vids так загружен мастер-портрет PNG в Ingredients: preview подтвердил загрузку референса, но не вставку в сцену и не создание клипа. Для вставки локального файла в сцену проверен **Insert → Upload** через **`vids_upload_via_picker`**; после загрузки проверь новый объект именно на canvas нужной сцены.

Если видна только кнопка Upload и input появляется по клику, используй **`vids_upload_via_picker`**: одним запросом передай `files` и наблюдаемый `nodeRef` кнопки **либо** её `x`/`y` в CSS-пикселях, а также текущие `sessionId`, `controlToken`, `snapshotId`, новый `operation_id`. Не делай обычный click в ожидании, что следующий инструмент обслужит системное окно. Оба пути принимают только разрешённые для задачи локальные медиа; текущую схему и проверки файлов задаёт MCP.

Новый метод включает interception до клика, проверяет реальное попадание указателя до и после hover, ждёт file chooser до пяти секунд, сверяет его фрейм и `input:file`, передаёт только указанные файлы и возвращает interception в режим отмены в `finally`. При тайм-ауте поздний chooser остаётся перехваченным в поддерживаемом target; квитанция с неизвестным исходом запрещает автоматический повтор. Наблюдай текущий статус и preview, затем принимай решение. Успешная квитанция не означает завершённую загрузку, вставку в сцену или генерацию.

Поддерживаются подключённый основной CDP target и проверенные same-origin фреймы в нём; cross-origin/OOPIF-цели отклоняются до клика, автоматического подключения к ним нет. Это не универсальная защита от любых OS-диалогов вредоносной страницы и не гарантия после detach. Если текущий UI выходит за этот путь, не обходи отказ через desktop automation.

Интеграционные фикстуры проверяют upload/picker, фреймы и guards. Они не доказывают, что конкретная операция прошла в текущем аккаунте. `performed: true` подтверждает отправленное действие, но его монтажный результат требует проверки UI и экспорта.

### Текстовый объект: сначала докажи режим редактирования

**Add a title создаёт объект, но не гарантирует вход в его текст.** Фокус может остаться на кнопке: в живом опыте Enter создал второй Title. Поле `Document content` в offscreen iframe также может быть focused в режиме выбора объектов. Ни этот фокус, ни Enter не доказывают текстовый режим. В живом монтаже Ctrl+A → Backspace в таком состоянии удалял объекты сцены, включая видео; `replace: true` использует те же клавиши.

Рабочая последовательность: Add a title → готовность UI и свежее observe/изображение → двойной клик по видимому тексту заголовка на canvas → новое observe и **видимый caret или выделение именно букв внутри нужного заголовка**. Рамка объекта или focused `Document content` этого подтверждения не заменяют. Без подтверждённого текстового режима не выполняй полную замену и не пробуй Ctrl+A как проверку фокуса.

Только после подтверждения текстового режима используй `vids_type_text` с `replace: true` для замены всего текста этого объекта. Для вставки в середину фразы полная замена не подходит. Затем Escape → свежее observe/изображение: проверь текст, переносы, сохранение, а также наличие исходного видео и остальных объектов сцены. Успешная квитанция ввода не доказывает их сохранность.

Не упаковывай эту последовательность в слепой макрос: текущий AX не сообщает достоверный диапазон выделения букв и полный устойчивый состав объектов сцены. Автоматическая проверка фокуса не заменяет эти две проверки. Если сложную графику приходится собирать десятками хрупких вводов, подготовь читаемые статичные элементы по [generation.md](generation.md#читаемые-интерфейсы-и-схемы) и используй Vids для их композиции и движения.

Если исчезли объекты, прекрати ввод и восстанавливай состояние через Undo с проверкой после каждого шага. Замена может попасть в историю как несколько изменений: в живой проверке один Undo удалил последнюю вставку, оставив пустой объект. Не рассчитывай, что одна отмена восстановит всю сцену, и не повторяй её вслепую. При диагностике можно вызвать `vids_observe` с `diagnostics: true`, но сведения о DOM-фокусе не заменяют визуальную проверку caret.

## Долгие операции и восстановление

Для заказанного MP4 используй доступный типизированный `vids_job_start(kind: export_mp4)` и собственные session/control, document ID и новый intent ID. Перед запуском требуется свежее evidence автоматического сохранения загрузок в этом Chrome-профиле без системного Save As; не выдумывай подтверждение и не меняй настройки скрытно. Job сам наблюдает File → Download → MP4, проверяет конкретную загрузку и сохраняет проверенную локальную копию. Пока этот сценарий поддерживает наблюдаемые английские labels; иной UI требует отдельной проверки. Нельзя передавать ему произвольный JS или список кликов.

До start создай и приватно сохрани `jobId` (UUID) и криптографически случайный `jobToken` (32 bytes в base64url), передай их вместе с intent. Они известны до ответа, поэтому потерянный ответ не лишает доступа к заданию. status/result/cancel требуют эту пару; повтор start с теми же аргументами и своим token только читает существующий статус, без новых кликов. Poll с backoff, не запускай новый intent по пустому progress. Отмена останавливает дальнейшие шаги; отправленный экспорт Google не объявляется отменённым. После перезапуска unresolved job не возобновляет клики: используй только предусмотренное текущей схемой обследование загрузки или явное завершение ожидания после native reconciliation и получения новой собственной lease. Потеря token не разрешает его подбор. [Контракт и ограничения jobs](../../../docs/jobs.md).

`vids_job_result` подтверждает provenance загрузки, путь, hash, длительность, размеры и decode. Текст речи, звучание, движение, captions и зрительская ясность проверяются отдельно. Для замены дубля используй [take manifest](take-manifest.md): прежний source сохраняется, а зависимые тайминги остаются открытыми до evidence. Manifest не изменяет таймлайн Vids.

Скриншот получает один кадр через `Page.startScreencast`, подтверждает его и сразу останавливает поток. Это обходит зависание `Page.captureScreenshot` на неподвижной фоновой странице. Сессия, эпоха snapshot и timestamp кадра проверяются; поздний кадр предыдущего захвата не становится новым наблюдением. PNG/JPEG, качество и масштаб CSS сохраняются. Поток не используется как параллельный fallback поверх зависшего capture.

После `BROWSER_TIMEOUT` именно от `vids_screenshot` сначала вызови `vids_status`. Новый режим определяется по `recovery.state: screenshot_read_pending`, `blocks: ["screenshot"]` и `timeoutMs: 10000`. Ответ приходит через 10 с; этот тайм-аут не отзывает подключение или управление и не запускает второй срок до detach. Старый snapshot недействителен: получи свежий `vids_observe`, затем продолжай допустимые действия по его данным. Пока исходное чтение не завершилось, новый screenshot получает `BROWSER_RECOVERING` без повторного capture; не опрашивай screenshot в цикле. Поздний результат отбрасывается и не заменяет свежий snapshot. Когда чтение завершится, `recovery` станет `null` и новый screenshot снова будет доступен. Если Chrome не подтвердил остановку потока (`screenshot_cleanup_failed`), новые снимки заблокированы до явного reconnect в паузе; observe остаётся доступным. Обычное истечение lease, смена документа и реальные обрывы всё ещё требуют соответствующего восстановления.

Не применяй этот порядок к старой сборке с `state: waiting_for_read`: она блокирует observe, screenshot и ввод, ждёт ещё до 10 с и отцепляет вкладку по hard deadline. В таком режиме ограниченно проверяй status в пределах объявленного срока; после `recovery: null` при прежней сессии нужен новый observe, после detach — явное переподключение и новое управление. Отсутствие поля `recovery` не подтверждает новую реализацию. Сверяй фактически загруженные версии/build; установка исходников не равна reload расширения.

При явном подключении обновлённый драйвер поддерживает отрисовку выбранной вкладки через CDP focus emulation. Это сообщает странице видимость/фокус, не активируя вкладку или окно и не используя системный ввод; debugger detach снимает override. Это не фокус конкретного текстового поля и не подтверждение caret. Скрытое или перекрытое окно всё ещё может не отдать кадр по другим причинам; один тайм-аут не устанавливает причину. Если для следующей правки нужна именно визуальная проверка, сохрани её как незавершённую, а не действуй по старому изображению или догадке. Ошибка текущего screenshot не разрешает читать оставшийся файл предыдущего снимка.

Отдельный случай — `BROWSER_TIMEOUT` от `vids_scroll`. В обновлённой сборке зависший `Input.dispatchMouseEvent` сохраняет attachment, но status показывает `recovery.state: input_ack_pending`, `blocks: ["mutations"]` и `requiresReconciliation: true`. AX/status доступны; все мутации, release управления и reconciliation заблокированы до фактического завершения исходной команды Chrome. Wheel мог ещё не отправиться и способен выполниться позже: не считай тайм-аут отменой и не переноси сюда разрешение свежего ввода из screenshot-режима.

Даже после позднего ACK или отказа исход scroll остаётся `unknown`. Получи свежий `vids_observe`, установи результат и выполни `vids_reconcile_control` с evidence перед новой мутацией. Исчезновение `input_ack_pending` само по себе не разрешает запись; ACK не доказывает прокрутку. Не повторяй scroll и не переключайся на другой жест для повторения того же намерения. Этот порядок требует фактически загруженного нового режима; остальные тайм-ауты мутаций сохраняют прежнюю остановку с отзывом подключения и явным reconnect. Не выводи Chrome вперёд и не используй системный ввод.

Тайм-аут мутации остаётся исходом `unknown`: не повторяй её автоматически, даже после восстановления. Сначала установи фактический результат в документе. Переподключение не превращает неизвестный исход в «не выполнено».

У генерации и экспорта различай запрос, ожидание, готовность и ошибку. Обновляй состояние с разумным интервалом, сообщай о существенном ожидании, не нажимай Generate повторно из-за отсутствия мгновенного результата. После отказа посмотри текст ошибки и доступность функции/языка/лимита; навык не может снять ограничение аккаунта.

Перед широким изменением существующего монтажа учитывай Undo и историю редактора; копию делай, когда она полезна и входит в задачу. Не плодить копии для каждого клика. При возобновлении сверяй реальный проект, текущие дорожки и статус сохранения, а не только собственный прошлый отчёт.

Для длинной сессии сохрани в разрешённом рабочем месте компактный checkpoint: URL проекта, замысел, что реально изменено и проверено, текущая сцена, открытые проблемы и следующий шаг. Session/snapshot ID после переподключения не считай действительными.


## Typed export job

При доступном `vids_job_start` поддерживается только `export_mp4`. Заранее создай и сохрани UUID jobId/intentId и случайный jobToken; повтор того же start возвращает статус без нового экспорта. Требуется свежее явное подтверждение автоматического скачивания без Save As; настройка браузера не меняется. Unknown не повторяется, recovery требует нового writer token и evidence, cancellation не означает отмену Google export. Технический succeeded не доказывает слуховую/зрительскую QA. Неподдерживаемое меню или недостаточная download correlation требуют reconciliation.

### Управление во время экспорта и путь к файлу

После job_start переданное управление использует runner: не освобождай и не получай его заново, не редактируй этот документ, пока задание queued/running/waiting. Читай job_status с backoff; параллельно готовь локальные материалы. Runner освобождает управление перед локальной проверкой файла. Запрос отмены не отменяет скачивание Chrome. EXPORT_STILL_PENDING означает, что ожидание браузера ещё не разрешено; не объявляй его очищенным и не проси автоматически новый pairing-код.

Квитанция различает frame_and_document и document_referrer. Второй способ опирается на свежее событие загрузки с полным referrer точно этого документа Vids и точный download ID; GUID Page не выдумывается. Один домен, пустой referrer или совпадение имени файла не доказывают происхождение. Если путь не получен, используй ограниченный локальный поиск из client-tools и проверь кандидатов. Не спрашивай путь у пользователя до проверки разрешённых каталогов загрузки.
